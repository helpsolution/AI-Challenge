# День 3 — разные способы рассуждения

Одна задача уходит в модель четырьмя разными промптами. Задача, модель и температура при
этом не меняются — меняется только формулировка вокруг задачи. Ответы показываются рядом,
а их финальные строки сводятся в одну таблицу: видно, разошлись способы или нет и во что
обошёлся каждый.

Развитие [дня 1](../day1) и [дня 2](../day2): клиент к DeepSeek, показ сырого HTTP-обмена,
параллельные прогоны и дизайн-система переиспользованы, добавлены способы рассуждения
и сравнение их результатов.

## Стек

## Четыре способа

Способы отличаются только тем, что уходит в system-prompt и сколько делается вызовов.
Каждый промпт показан в интерфейсе целиком — иначе сравнение пришлось бы принимать на веру.

**1. Прямой ответ** — 1 запрос. Задача уходит как есть: ни роли, ни метода, ни требования
рассуждать. Системной инструкции нет вовсе.

**2. Пошаговое решение** — 1 запрос. Та же задача плюс инструкция разбить решение
на пронумерованные шаги, в каждом выполнять ровно одно действие и в конце подставить
результат обратно в условие.

**3. Промпт от самой модели** — 2 запроса. Первый просит модель не решать задачу, а написать
промпт для её решения: роль, метод рассуждения, ловушки в условии, форма ответа. Промпт
требуется самодостаточный — с полным текстом задачи внутри. Вторым запросом этот
сочинённый промпт и отправляется. В интерфейсе видно оба шага.

**4. Группа экспертов** — 1 запрос. Модель отыгрывает аналитика, инженера и критика по
очереди, каждый даёт своё решение, затем подводится итог. Ответ приходит размеченным
заголовками, и приложение раскладывает его по ролям.

Эксперты живут внутри одного вызова и видят рассуждения друг друга. Это дёшево — но
и склоняет их соглашаться: критик читает решение инженера, а не приходит к своему
независимо.

## Общая добавка

Чтобы финальные ответы можно было сопоставить, ко всем способам добавляется одна общая
строка: закончить ответ маркером `ОТВЕТ: <ответ>`. Это единственная инструкция, общая для
всех четырёх, — включая прямой ответ, который по замыслу идёт вообще без инструкций.

Компромисс осознанный и выключается тумблером. С добавкой прямой запрос перестаёт быть
совсем голым; без неё финальный ответ берётся из последней непустой строки — грубее
и иногда промахивается.

## Как сравниваются ответы

Сравнивать способы по полному тексту бессмысленно: пошаговое решение и разбор группы
экспертов не совпадут никогда, даже придя к одному результату. Поэтому сравнивается
только строка после маркера, приведённая к сопоставимому виду:

```
«**44 раза**.»  →  44
«44»            →  44
«38,5 года»     →  38.5
```

Гасятся регистр, `ё`, markdown, пунктуация и запятая в дробях. Отдельно снимается единица
счёта: `44` и `44 раза` — один ответ. Хвост отбрасывается только если он целиком состоит
из слов-единиц (`раза`, `лет`, `процентов`, `в сутки`…). Правила «не больше пары слов»
тут мало: `12 процентов роста` и `12 процентов падения` по длине неотличимы, а по смыслу
противоположны.

Сравниваются строки, а не смысл. `один фрукт` и `1 фрукт` останутся разными ответами —
и это видно в интерфейсе честно, без попытки угадать за пользователя.

## API

### `POST /api/solve`

```json
{
  "task": "Сколько раз в сутки часовая и минутная стрелки образуют прямой угол?",
  "model": "deepseek-chat",
  "params": { "temperature": 0 },
  "techniques": ["DIRECT", "STEP_BY_STEP", "META_PROMPT", "EXPERT_PANEL"],
  "requireAnswerLine": true,
  "answerMarker": "ОТВЕТ:"
}
```

Возвращает по одному `run` на способ и сводку `comparison`.

| Поле `run` | Что показывает |
|---|---|
| `steps` | все вызовы способа по порядку: system-prompt, запрос, ответ, HTTP-обмен |
| `answer` | полный текст последнего ответа |
| `finalAnswer` | строка после маркера — только по ней способы и сравниваются |
| `sections` | ответ, разложенный по заголовкам (заполняется у группы экспертов) |
| `calls`, `promptTokens`, `completionTokens`, `latencyMs` | цена способа |
| `failure` | заполняется, если способ упал; остальные способы всё равно возвращаются |

| Поле `comparison` | Что показывает |
|---|---|
| `groups` | способы, сгруппированные по одинаковому финальному ответу |
| `allAgree` | все ли пришли к одному; `null`, если сравнивать не с чем |
| `fastest`, `leanest` | самый быстрый и самый экономный по токенам |

`wallClockMs` — реальное время прогона. Способы идут параллельно на виртуальных потоках,
поэтому оно заметно меньше суммы их латентностей.

Упавший способ не роняет остальные — приходит с `failure`. Но если упали все, причина общая
(ключ, баланс, сеть), и она отдаётся одной понятной ошибкой `502`, а не четырьмя одинаковыми
красными карточками.

### `GET /api/techniques`

Справочник способов: `id`, название, описание, число запросов. Фронт берёт названия отсюда,
а не дублирует их у себя.

### `GET /api/models`

Белый список моделей и модель по умолчанию.

## Наблюдения на живых запросах

Всё ниже — `deepseek-chat`, `temperature: 0`, маркер включён.

**«Сколько раз в сутки стрелки образуют прямой угол?»** (верно — 44)

| Способ | Ответ | Токенов ответа | Время |
|---|---|---|---|
| Прямой ответ | 44 | 437 | 4.6 с |
| Пошаговое решение | 44 раза | 355 | 3.7 с |
| Промпт от самой модели | 44 | 3467 | 24.9 с |
| Группа экспертов | 44 | 1519 | 12.4 с |

Прогон целиком — 24.9 с при сумме латентностей 45.6 с: параллельность съедает почти половину.

**«Когда мне было 3 года, сестре было вдвое меньше. Сейчас мне 40»** (верно — 38,5)

| Способ | Ответ | Токенов ответа | Время |
|---|---|---|---|
| Прямой ответ | 38.5 | 101 | 1.3 с |
| Пошаговое решение | 38.5 лет | 203 | 2.3 с |
| Промпт от самой модели | 38.5 | 317 | 14.0 с |
| Группа экспертов | 38.5 лет | 531 | 4.9 с |

**«Три коробки с неверными наклейками»** (верно — 1 фрукт из коробки «яблоки и апельсины»)

Все четыре ответили верно, но прямой ответ написал «один фрукт из коробки с надписью…»,
а остальные — «1 фрукт из коробки с наклейкой…». Строки разные, смысл один: ровно тот
случай, где сравнение по тексту упирается в свой потолок.

### Отличаются ли ответы

На этих задачах — почти нет. Три прогона из четырёх дали одинаковый финальный ответ у всех
четырёх способов; расхождения оказались словесными, а не смысловыми.

Единственное настоящее расхождение поймалось на первом прогоне задачи про стрелки: группа
экспертов выдала **64** вместо 44, остальные три способа — 44. На повторе того же запроса
с той же `temperature: 0` эксперты ответили уже 44. То есть расхождение дал не способ,
а недетерминированность провайдера: `temperature: 0` у DeepSeek не гарантирует одинаковый
ответ. Проверка стабильности из [дня 2](../day2) здесь оказалась бы кстати — одного прогона
на способ мало, чтобы делать выводы.

### Какой способ дал наиболее точный результат

По этим задачам разницы в точности нет: `deepseek-chat` решает их и без ухищрений.
А вот в цене разница большая:

- **Пошаговое решение** — лучший размен. Дешевле и быстрее прямого ответа (модель не льёт
  воду, а идёт по шагам), а рассуждение можно проверить глазами.
- **Прямой ответ** — самый короткий, но проверять в нём нечего: ответ приходит без обоснования
  или с обоснованием «задним числом».
- **Промпт от самой модели** — в 8–10 раз дороже по токенам и в 5–6 раз дольше при том же
  ответе. Модель тратит целый вызов на инструкцию себе самой. Оправдан там, где задачу
  формулирует не специалист и промпт для неё ещё надо придумать.
- **Группа экспертов** — вдвое-втрое дороже пошагового и единственный, кто в наших прогонах
  ошибся. Взгляд критика полезен на задачах с ловушкой, но внутри одного вызова эксперты
  соглашаются друг с другом слишком охотно.

Оговорка: это три задачи и по одному прогону на способ. Утверждать «способ X точнее» на такой
выборке нельзя — приложение и не утверждает: оно показывает ответы рядом и считает то, что
считается объективно (совпадение строк, токены, время). Вывод о точности остаётся за человеком.

## Тесты

```bash
./gradlew test
```

35 тестов: сборка промптов каждого способа, выделение финального ответа (маркер с конца,
markdown-обрамление, парные кавычки, запасной путь без маркера), нормализация (единицы счёта
против противоположных ответов с одним числом), разбор ответа на роли, два вызова мета-промпта
с передачей сочинённого промпта во второй, группировка ответов, изоляция упавшего способа
и общая ошибка, когда упали все.
