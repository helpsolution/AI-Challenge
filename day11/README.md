# День 11 - редактор постов с тремя слоями памяти

Один диалог соответствует одному посту. Редактор ведет автора через четыре этапа: идея, тезис, план, черновик. Переходы не требуют команд от пользователя: агент задает вопросы, предлагает тезис и план, пишет и правит текст. К предыдущему этапу можно вернуться; готовый текст можно принести сразу.

## Запуск

```bash
cp .env.example .env
./gradlew bootRun
```

Открыть http://localhost:8090. Для ответов модели нужен `OPENROUTER_API_KEY` в `.env`. По умолчанию используется `openai/gpt-4.1-mini` через OpenRouter. Данные хранятся в `data/day11.db`.

## Маршрутизация памяти

| Слой | Хранилище | Правило записи |
| --- | --- | --- |
| Краткосрочная | `message` | Каждая реплика сохраняется автоматически; модели передаются только последние `window_size` сообщений. |
| Рабочая | `post_task` | Модель возвращает отдельный `taskUpdate`; бэкенд проверяет этап и сохраняет идею, тезис, план, черновик и замечания текущего поста. |
| Долговременная | `memory_item` | Правило стиля записывается после кнопки "Запомнить", ручной записи или явной просьбы "запомни ..." в чате. |

Модель отвечает JSON-объектом с `reply`, `taskUpdate` и `styleSuggestion`. Пользователь видит только `reply`. Неподтвержденное `styleSuggestion` остается в рабочей памяти и не влияет на будущие посты. Удаление диалога удаляет его сообщения и рабочее состояние, но не подтвержденные долговременные правила.

## Сценарий проверки

1. Создать новый пост и описать тему своими словами. Убедиться, что тема появилась в рабочей памяти, а разговор - в краткосрочной.
2. Уточнить тезис, принять предложенный план и попросить черновик. Проверить переходы этапов и содержимое `post_task` на экране.
3. Сказать "Сделай этот финал короче". Правка должна касаться текущего поста, но не становиться долговременным правилом.
4. Сказать "Запомни: в будущих постах не делай назидательных выводов" или подтвердить предложенное правило кнопкой. Создать другой пост и проверить, что агент учитывает правило без старого диалога.
5. Удалить первый пост. Его переписка и рабочая память исчезнут; подтвержденное правило останется.

Старые данные черновой версии в таблице `task_memory` не удаляются. Новая версия использует `post_task`.
