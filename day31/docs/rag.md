# RAG по документации проекта

## Корпус

Корпус читается непосредственно из `PROJECT_ROOT`: корневые `README.md` и `docs/**/*.md`, а также `dayN/README.md` и `dayN/docs/**/*.md`. Только каталоги вида `day1`, `day28` и `day31` считаются днями. Каталоги с другим именем, приватные лекции, .env, базы данных и исходники в корпус не включаются.

Путь исходного документа сохраняется в каждом фрагменте. Название документа содержит путь и его главный заголовок. В интерфейсе источники показывают путь, раздел, строки и текст фрагмента.

## Индексация

Структурная нарезка переиспользована из дня 28: учитывает заголовки Markdown, списки, таблицы и блоки кода. Целевой размер — 1400 символов, максимальный — 2200 символов. Шапки длинных таблиц и ограждения длинных блоков кода повторяются для сохранения контекста.

Эмбеддинги строит модель `nomic-embed-text` в Ollama через `/api/embed`. Для документов добавляется префикс `search_document: `, для вопросов — `search_query: `. Запросы используют `truncate: false`: текст не должен молча обрезаться.

Векторы, фрагменты и метаданные хранятся в SQLite. SHA-256 учитывает документы, настройки нарезки и модель эмбеддингов. Перед каждым поиском проверяется актуальность индекса. При изменениях индекс пересобирается; кнопка «Обновить индекс» принудительно запускает пересборку. Ошибка пересборки останавливает поиск, чтобы ответ не строился по устаревшей документации.

## Поиск

Выбор `dayN` ограничивает кандидатов документами этого дня до реранкинга. При выборе всего репозитория поиск идёт по всем индексированным документам. Явное упоминание дня в вопросе заменяет выбор в интерфейсе.

Первый этап — косинусная близость, до 20 кандидатов. Второй — `bge-reranker-v2-m3` на llama.cpp, до 5 фрагментов. В контекст попадают только фрагменты с сырой оценкой BGE не ниже 0. Эта оценка не является вероятностью. Если ни один фрагмент не проходит порог, модель не вызывается.

Для короткого уточнения, начинающегося с «а», «он», «она», «это», «тогда» или «подробнее», поисковый запрос дополняется предыдущим вопросом пользователя. В интерфейсе история ограничена тремя обменами и отбирается только для текущего проекта.

## Проверка ответа

DeepSeek возвращает JSON с `status`, `answer` и `quotes`. Ответ должен содержать ссылки `[n]`. Каждая ссылка должна иметь цитату из соответствующего текущего фрагмента. Цитата проверяется по исходному тексту с допуском различий оформления пробелов, кавычек, тире и Markdown.

Обрезанный ответ, невалидный JSON, выдуманная цитата или ссылка без цитаты отклоняются. Модель получает одну попытку исправления с причинами отказа и теми же источниками. Оба ответа и обе проверки сохраняются в трассировке. Если исправление также не прошло проверку, возвращается `unverified`. Модель может вернуть `unknown`, если фрагменты не содержат ответа. Источники документации и MCP имеют общую нумерацию внутри одного ответа. Токены в интерфейсе суммируются по обеим попыткам.
