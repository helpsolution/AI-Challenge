# День 4 — температура

Один и тот же запрос уходит в модель на нескольких температурах сразу. Запрос, модель
и инструкции при этом не меняются — меняется ровно один параметр. Каждый ответ показан
отдельной карточкой во всю ширину и помечен цветом своего диапазона: 🧊 точность,
🌤 баланс, 🔥 креатив, 🌋 перегрев. Под ответами — то, что в них можно посчитать
объективно: длина, разнообразие лексики и расстояние между ответами.

Развитие [дня 3](../day3): клиент к DeepSeek, показ сырого HTTP-обмена, параллельные
прогоны, выделение финальной строки и дизайн-система переиспользованы; добавлены шкала
температуры, метрики текста и мера различия ответов.

## Стек

| Слой | Технологии |
|---|---|
| Backend | Kotlin 2.3, Spring Boot 4.1, Gradle Kotlin DSL, JDK 21 |
| Frontend | Vue 3 (CDN), дизайн-система Halo Light |
| LLM | DeepSeek (`deepseek-chat`) |

## Запуск

```bash
cp .env.example .env          # и вписать свой ключ с platform.deepseek.com
./gradlew bootRun
```

Открыть http://localhost:8083 (дни 1–3 занимают 8080–8082, приложения не конфликтуют).

Модель одна: `deepseek-reasoner` температуру игнорирует, и день 4 на нём превратился бы
в три одинаковых запроса. Белый список в `application.yml` это и фиксирует.

## Четыре диапазона

Границы условные: у провайдера нет ступенек, есть плавный рост разброса. Диапазоны
описаны в `TemperatureBand` и отдаются фронту через `GET /api/bands` — интерфейс строит
по ним справочник и определяет цвет полосы, а не дублирует пороги у себя.

| | Диапазон | Подходит | Не подходит |
|---|---|---|---|
| 🧊 **Точность** | 0.0 – 0.3 | извлечение данных, JSON, арифметика, код, перевод, классификация | тексты для людей, подбор вариантов |
| 🌤 **Баланс** | 0.4 – 0.9 | деловая переписка, описания, объяснения, чат-ассистент | ответы, которые сравниваются между прогонами; строгие форматы |
| 🔥 **Креатив** | 1.0 – 1.5 | слоганы, названия, мозговой штурм, художественный текст | факты и числа, задачи с одним правильным ответом |
| 🌋 **Перегрев** | 1.6 – 2.0 | показать, как ломается генерация | всё остальное |

## Что здесь измеряется, а что нет

Задание просит сравнить ответы по точности, креативности и разнообразию. Из трёх осей
двух объективных мер не существует, и приложение их не изображает:

**Точность.** Эталонных ответов нет, LLM-судьи нет. Вместо оценки — почва для неё:
одинаковый запрос, ответы рядом и необязательное требование финальной строки `ОТВЕТ: …`.
Финальные строки всех прогонов группируются по совпадению (нормализация из [дня 3](../day3):
`«2208 рублей»` и `«2208»` — один ответ). Одна группа означает, что ответ не изменился
ни на одной температуре; несколько — что где-то поплыл. Верен ли он — решает человек.

**Креативность.** Мерится косвенно — разнообразием лексики. Считается не как «уникальных
слов / всего слов»: такая доля механически падает с длиной текста, а длина с температурой
как раз меняется. Взят MATTR — доля неповторяющихся слов в скользящем окне 50 слов,
усреднённая по всем окнам. Длина на неё не влияет, поэтому короткий и длинный ответ
сравнимы. На перегреве метрика ломается в обратную сторону: выдуманные слова уникальны
все до одного, и 0.98 там означает не богатство, а бессвязность.

**Разнообразие.** Это свойство *набора* ответов, по одному прогону его не измерить.
Поэтому считаются две разные вещи:

- **разброс внутри температуры** — среднее расстояние между прогонами одной температуры.
  Требует двух прогонов и больше, число прогонов задаётся в панели (1–5);
- **отличие между температурами** — среднее расстояние между ответами разных температур.
  Работает и при одном прогоне и отвечает на вопрос «меняет ли температура ответ вообще».

Расстояние — доля пар соседних слов, которые есть в одном ответе и отсутствуют в другом
(расстояние Жаккара по биграммам). Считается по парам слов, а не по отдельным словам:
у ответов на один запрос отдельные слова совпадают почти всегда, различает их порядок.
Это мера различия **текста, а не смысла**: два верных ответа, сказанных разными словами,
дадут большое число. Поэтому оно сравнивается с другими такими же числами, а не толкуется
само по себе.

## API

### `POST /api/compare`

```json
{
  "prompt": "Придумай пять названий для маленькой кофейни у метро",
  "model": "deepseek-chat",
  "temperatures": [0, 0.7, 1.2],
  "runs": 1,
  "requireAnswerLine": false,
  "answerMarker": "ОТВЕТ:"
}
```

До четырёх температур из диапазона 0.0–2.0 и до пяти прогонов на каждую. Дубли схлопываются,
полосы возвращаются по возрастанию. Все запросы идут параллельно на виртуальных потоках.

| Поле `lane` | Что показывает |
|---|---|
| `temperature`, `band`, `title`, `emoji` | сама температура и её диапазон |
| `runs` | прогоны: ответ, метрики, финальная строка, сырой HTTP-обмен |
| `metrics` | метрики, усреднённые по удавшимся прогонам |
| `selfSpread` | разброс между прогонами этой температуры; `null` при одном прогоне |
| `distinctAnswers` | сколько среди прогонов дословно различных ответов |
| `completionTokens`, `latencyMs`, `failures` | цена полосы |

| Поле `comparison` | Что показывает |
|---|---|
| `distances` | расстояние по каждой паре температур |
| `richest`, `mostVaried`, `longest`, `shortest`, `fastest` | температура-рекордсмен по каждой мере |
| `answerGroups` | финальные строки, сгруппированные по совпадению (только с маркером) |

Упавший прогон не роняет остальные — приходит с `failure`. Но если упали все, причина общая
(ключ, баланс, сеть), и она отдаётся одной понятной ошибкой `502`.

### `GET /api/bands`

Справочник диапазонов: границы, описание, списки «подходит» и «не подходит».

### `GET /api/models`

Белый список моделей и модель по умолчанию.

## Наблюдения на живых запросах

Всё ниже — `deepseek-chat`, реальные прогоны.

### Творческая задача: пять названий для кофейни

Один прогон на температуру, без маркера.

| Температура | Слов | Разнообразие лексики | Токенов | Отличие от ответа при 0 |
|---|---|---|---|---|
| 0.0 | 210 | 92 % | 533 | — (эталон) |
| 0.7 | 222 | 92 % | 489 | 90 % |
| 1.2 | 247 | 90 % | 593 | 97 % |

Названия при 0.0 — «Турникет», «Пять минут», «Эскалатор», «Вагон-эспрессо», «Последний вагон»:
прямые ассоциации с метро. При 1.2 — «Перегон», «Узелок», «Кратчайший путь», «Эскалаторы»,
«Место встречи»: ассоциации дальше от буквального. Разница ровно та, ради которой греют.

### Задача с одним правильным ответом: арифметика

«Товар стоил 2400, подорожал на 15 %, потом уценили на 20 %» (верно — 2208).
Три прогона на температуру, маркер включён.

| Температура | Слов | Разброс внутри | Различных ответов | Финальные строки |
|---|---|---|---|---|
| 0.0 | 23 | 13 % | 2 из 3 | 2208, 2208, 2208 |
| 0.7 | 23 | 60 % | 3 из 3 | 2208, 2208, 2208 |
| 1.2 | 19 | 59 % | 3 из 3 | 2208, 2208, 2208 |

Все девять прогонов дали верный ответ: на арифметике такого уровня температура влияет
на формулировку решения, а не на результат. Растёт при этом именно разброс текста:
13 % при нуле против ~60 % выше.

### Проверка фактов

«Назови три страны, столица которых не крупнейший город» — два прогона, маркер включён.

| Температура | Разброс внутри | Что ответила модель |
|---|---|---|
| 0.0 | 0 % | оба раза США, Канада, Австралия |
| 0.7 | 86 % | США/Канада/Турция, затем Казахстан/Бразилия/США |
| 1.2 | 61 % | США/Канада/Бразилия, затем США/Австралия/Канада |

Фактических ошибок не появилось ни на одной температуре — все названные пары «столица —
крупнейший город» верны. Изменился не факт, а *выбор* факта: при нуле модель каждый раз
берёт один и тот же очевидный набор, при 0.7 и выше — разные. Для вопроса «дай три примера»
это скорее плюс, для вопроса «дай тот самый ответ» — минус.

### Извлечение данных в JSON

Один прогон на температуру, добавлена 2.0.

Все четыре ответа — включая **2.0** — вернули один и тот же JSON, с точностью до
markdown-обёртки (при 1.2 модель отдала его без ```-блока и в одну строку). Расстояние
между 0.0 и 2.0 — 0 %.

Вывод, которого не было в задании: температура влияет не одинаково. Когда следующий токен
почти предопределён условием — данные в запросе есть, форма задана, — распределение
настолько острое, что даже 2.0 из него не выбивает. «Горячо» не значит «испортится»:
значит «есть из чего выбирать».

### Перегрев: 2.0 на художественном тексте

Тот же вопрос на задаче с широким распределением выглядит совсем иначе. Начало рассказа,
`temperature: 2.0`:

> Резкий, дребезжащий звонок полоснул по утробной тишине спальни сливовым вареньем — старый
> телефон, питомец ещё моей бабушки, будто бы встрепенулся после трёхлетнего **спругомого**
> забытья… **Груз Пы винтаЖ может начать крутиТСЯ повторПуси входИ Техто сим Лет Полнее —
> сегМеш Тиши.**

Первое предложение ещё держится, дальше связность рвётся, появляются несуществующие слова
и сбитый регистр. Разнообразие лексики при этом — 98 %, самое высокое в прогоне: наглядно
видно, почему эту метрику нельзя читать как «креативность».

### Температура 0 — это не детерминизм

Тот же запрос при `temperature: 0` даёт разные ответы. На арифметике разброс между тремя
прогонами — 13 % (различаются формулировки шагов), на начале рассказа между двумя
прогонами — **90 %**: два совершенно разных текста при нулевой температуре. Ноль означает
«всегда самый вероятный токен», а не «одинаковый ответ»: провайдер не гарантирует
воспроизводимость, и на широком распределении это видно сразу.

Наблюдение подтверждает то, что в [дне 3](../day3) поймалось случайно: одного прогона
на настройку мало, чтобы делать выводы.

### Выводы по настройкам

- **0 – 0.3** — там, где ответ проверяется, а не читается: извлечение данных, JSON, код,
  арифметика, классификация. Разброс минимален, но не нулевой.
- **0.4 – 0.9** — тексты для людей, где смысл важнее оригинальности: письма, описания,
  объяснения. Рабочее значение по умолчанию.
- **1.0 – 1.5** — там, где нужны варианты: названия, слоганы, штурм, проза. Проверять
  факты в таких ответах приходится отдельно.
- **1.6 – 2.0** — прикладной пользы нет; полезно один раз увидеть, чтобы понимать,
  что происходит с генерацией при росте температуры.

Общая оговорка: это несколько задач и по одному-три прогона на температуру. Утверждать
«при X точнее» на такой выборке нельзя — приложение и не утверждает. Оно показывает ответы
рядом и считает то, что считается объективно; вывод о качестве остаётся за человеком.

## Разметка ответов

Модель отвечает markdown-ом, и показывать его сырым — со звёздочками вместо жирного —
значит мешать сравнивать тексты глазами. В интерфейсе есть маленький рендерер: заголовки,
списки, жирный, курсив, код и ```-блоки. Две вещи в нём сделаны намеренно:

- текст экранируется **целиком** до того, как в него добавляется первый тег, поэтому ответ
  модели не может принести на страницу свою разметку или скрипт;
- нумерация списка продолжается с того числа, которое поставила модель (`<ol start="…">`).
  Показать «1.» там, где в ответе «3.», значит переписать ответ за неё.

## Тесты

```bash
./gradlew test
```

40 тестов: границы диапазонов, разбор текста на слова и предложения, независимость
разнообразия лексики от длины, мера различия ответов, а через MockMvc со стабом провайдера —

и что невалидные параметры отсекаются до похода в сеть.
