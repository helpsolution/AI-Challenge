# День 13 — состояние задачи

Редактор постов с формализованным состоянием задачи. Проект продолжает `day12 Hard`, но хранится и запускается отдельно.

## Конечный автомат

Работа над постом проходит через четыре предметных состояния:

```text
IDEA → THESIS → PLAN → DRAFT
```

Для каждого состояния в SQLite сохраняются:

- этап задачи (`state`);
- текущий шаг (`currentStep`);
- ожидаемое действие пользователя (`expectedAction`);
- уже собранные идея, тезис, план, черновик и замечания.

Переходы проверяет бэкенд по явной карте. Разрешены движение вперед, работа внутри текущего этапа и осмысленный возврат к предыдущим этапам. Модель не может произвольно перескочить через этап.

Пауза не требует отдельного статуса: состояние постоянно хранится в `post_task`. После перезапуска приложения или возвращения к старой сессии сообщение «Продолжай» передается модели вместе с этапом, текущим шагом и ожидаемым действием — повторно объяснять задачу не нужно.

## Запуск

```bash
cp .env.example .env
./gradlew bootRun
```

Открыть http://localhost:8093. Карта агента доступна по адресу http://localhost:8093/inside.html.

Для ответов модели нужен `OPENROUTER_API_KEY`. По умолчанию используется `openai/gpt-4.1-mini` через OpenRouter, данные сохраняются в `data/day13.db`.

## Проверка

```bash
./gradlew test
```

Тесты проверяют допустимые переходы, запрет пропуска этапа, возврат к тезису и продолжение после паузы на каждом из четырех этапов без повторной передачи старого объяснения.
