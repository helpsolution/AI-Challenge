# Правила проекта бронирований

1. Контроллер разбирает HTTP и вызывает сервис. Бизнес-проверки, в том числе длительность брони, живут в BookingService. Контроллер не обращается к BookingRepository напрямую.
2. Бронь длится от 15 минут до 4 часов; начало и конец кратны 15 минутам.
3. Изменить или отменить бронь может только автор. Начавшуюся бронь не меняют.
4. Текущее время берётся из Clock, хранится как Instant в UTC.
5. Проверка пересечений и запись выполняются атомарно. Изменяющие методы BookingService защищены @Synchronized.
6. Пересечения считаются по полуинтервалам в Booking.overlaps.
7. Сбой уведомления не отменяет бронь. Токен уведомлений не попадает в журнал.

## Формат отчёта

Для каждой проверки: правило, результат (нарушено / соблюдено / недостаточно данных), файл и строки с доказательством. Не выдавай предположения за найденные нарушения. Отдельно укажи ограничения проверки.
