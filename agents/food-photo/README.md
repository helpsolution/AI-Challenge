# Агент распознавания еды по фото

Отдельное приложение на Kotlin и Spring Boot. Принимает фото блюда и за один запрос к визуальной модели через OpenRouter возвращает вероятное название, описание видимого и список предположительных ингредиентов. Если еды на фото нет, модель сообщает об этом. Точный состав, массу и калории приложение не определяет.

## Запуск

Нужен JDK 21. В текущей рабочей папке `.env` уже создан с ключом OpenRouter из `day14`; файл игнорируется Git. Для нового окружения из папки `agents/food-photo`:

```bash
cp .env.example .env
# Укажите действующий OPENROUTER_API_KEY в .env
./gradlew bootRun
```

Если `.env` уже есть, просто запустите `./gradlew bootRun`.

Приложение по умолчанию слушает порт `8097`. Ключ хранится на сервере и не передаётся клиентом. Модель по умолчанию — `google/gemini-2.5-flash-lite`. Порт и модель меняются переменными `PORT` и `OPENROUTER_MODEL`.

## Отправка фото

Откройте [Swagger UI](http://localhost:8097/swagger-ui/index.html) и вызовите `POST /api/food/describe`, выбрав файл в поле `image`. Поддерживаются JPEG, PNG и WebP до 5 МБ.

Либо отправьте файл через curl:

```bash
curl -sS http://localhost:8097/api/food/describe -F 'image=@/путь/к/фото.jpg'
```

Пример ответа:

```json
{
  "dishName": "Паста с томатным соусом",
  "description": "На тарелке видна паста с красным соусом и зеленью.",
  "likelyIngredients": ["паста", "томаты", "зелень"]
}
```

Описание основано только на фото; модель может ошибаться в названии и ингредиентах. Для оценки фактической стоимости отдельного запроса смотрите `usage.cost` в ответе OpenRouter или историю расхода в его кабинете.
