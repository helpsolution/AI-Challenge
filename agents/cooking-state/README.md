# Агент «Что приготовить?»

Отдельное приложение на Kotlin и Spring Boot. На каждом сообщении агент вызывает LLM через OpenRouter, получает обновлённый контекст и предложение о следующем состоянии. Код проверяет переход и сохраняет сессию в SQLite. После перезапуска приложения диалог можно продолжить по тому же `id`.

Состояния диалога:

| Состояние | Что происходит |
| --- | --- |
| `GATHERING` | Агент узнаёт продукты и время. Порции и ограничения необязательны. |
| `CHOOSING` | Агент предлагает 2–3 блюда. Можно уточнить продукты, время или ограничения и обновить варианты. |
| `READY` | Блюдо выбрано: агент сохраняет рецепт и ждёт команды начать. |
| `COOKING` | Агент показывает один шаг, отвечает на вопросы и переходит дальше после «готово». |
| `DONE` | Все шаги завершены; по «начать заново» очищается контекст сессии. |

Шаги хранятся в `context.recipe.steps`, а `context.currentStepIndex` указывает текущий шаг с нуля. В состоянии `DONE` индекс равен числу шагов. Модель предлагает переход, но код проверяет допустимость перехода и не даёт пропустить шаг.

## Запуск

Нужен JDK 21. В этой рабочей папке `.env` уже создан с ключом OpenRouter из соседнего проекта; файл игнорируется Git. Для нового окружения:

```bash
cd agents/cooking-state
cp .env.example .env
# Укажите OPENROUTER_API_KEY в .env
./gradlew bootRun
```

Если `.env` уже есть, достаточно `./gradlew bootRun`. По умолчанию порт `8098`, база — `data/cooking-state.db`, модель — `google/gemini-2.5-flash-lite`.

## Проверка через Swagger

Откройте [Swagger UI](http://localhost:8098/swagger-ui/index.html):

1. Вызовите `POST /api/sessions`. Скопируйте `id` из ответа.
2. Вызовите `POST /api/sessions/{id}/messages` с `{"text":"Есть яйца и сыр"}`. Агент должен уточнить время.
3. Повторите с `{"text":"15 минут, одна порция"}`. Состояние должно стать `CHOOSING` и появятся варианты блюд.
4. Напишите `{"text":"Выбираю омлет"}` (или точное название одного из вариантов). Состояние станет `READY`, в `context.recipe` появятся шаги.
5. Напишите `{"text":"Начинаем"}`. Состояние станет `COOKING`, в ответе появится первый шаг.
6. Напишите `{"text":"Как это сделать?"}`: агент ответит, сохранив номер шага. Затем отправляйте `{"text":"Готово"}` после каждого шага. После последнего состояние станет `DONE`.
7. Вызовите `GET /api/sessions/{id}` для просмотра сохранённого состояния. Перезапустите приложение и повторите GET: данные останутся. Сообщение `{"text":"Начать заново"}` очищает контекст.

В каждом ответе есть `state`, `context`, `reply`, `version` и `updatedAt`. `version` увеличивается после каждого успешного сообщения. Одновременные обновления одной сессии защищены проверкой версии и могут вернуть HTTP 409; в этом случае повторите сообщение после GET.

## Проверка через curl

```bash
curl -sS -X POST http://localhost:8098/api/sessions
curl -sS -X POST http://localhost:8098/api/sessions/ID/messages \
  -H 'Content-Type: application/json' -d '{"text":"Есть яйца и сыр, 15 минут"}'
curl -sS http://localhost:8098/api/sessions/ID
```

Вместо `ID` подставьте `id` созданной сессии. Для новой беседы создайте новую сессию. Ключ OpenRouter находится только на сервере.
